## 2. Where they MUST differ (substrate-real — permanent)

Unchanged from 05-22, and the openai-codex migration doesn't alter them:
- **Context reduction:** MS4CC = Claude Code compaction (can't gate); MindStone = sliding window, compaction refused.
- **Dream-cycle automation:** MS4CC can't auto-fire a consolidation prompt (no in-turn hook); MindStone can (memoryFlush after each turn).
- **Session lifecycle:** MS4CC bounded by Claude Code SessionStart/Stop (`/exit` skips Stop); MindStone `session.reset.mode: "never"`.
- **Session-resume cap:** a MindStone concern only — it exists because MindStone re-loads a multi-million-token append-only JSONL into a live runtime on restart. MS4CC never re-loads a session into a runtime it owns, so it has no analog (and no analogous orphan bug).

---

## 3. Where they CONVERGED since 05-22 (the actionable part — now done)

- **Embedder model → nomic-embed-text (768d) on both.** The 05-22 §3.1/§6.1 ask is closed. Caveat: convergence is **model-level only**. The stores are still separate (sqlite-vec vs LanceDB) and vectors are **not cross-queryable** across substrates — a Cairn-side memory and a Mira-side journal still can't be searched in one query. Cross-substrate retrieval remains future work.
- **Chunk ceiling → real model token limit on both.** #35 (MS4CC) and #165 (MindStone) independently fixed the same silent-embed-failure class in the same week. The lesson (nomic's advertised 8192 is a lie; real ceiling 2048) is now encoded in both codebases.
- **Per-item embed resilience (MS4CC) / hardSplit (MindStone).** Both moved from "one oversized chunk kills the batch" to "split below ceiling, never silently drop the batch."

---

## 4. Where they STILL diverge by drift (the open asymmetry)

**Per-turn experiential weighting.** This is the one 05-22 finding that did NOT converge:
- **MindStone Proper closed it** — `applyExperientialRerank` (the 6-component "D9" re-rank) runs on every autoRecall fire.
- **MS4CC has not** — per-turn recall is still pure cosine + MMR; weight only fires at SessionStart selection.

Consequence (unchanged): on MS4CC, a high-`prevented`/high-`hits` memory that isn't cosine-close to the current prompt will lose to a closer-but-trivial chunk on a per-turn recall. Half of "memory that learns" still doesn't fire on MS4CC. Fix is tractable (second-pass re-rank in `recall.py`); decision pending.

## 5. Where they differ by design (keep different)

- **Daily journals (MindStone) vs LOG.md (MS4CC).** First-person experiential vs session-summary. The optional `/journal` cross-pollination idea (05-22 §4.1) remains unbuilt.
- **Karpathy-wiki (MS4CC) vs database-centric (MindStone).** Resolved 05-22; unchanged.

## 7. The drift meta-point (still true)

Cairn's 05-22 framing holds: the three drift causes were (1) conflating MS4CC and MindStone Proper, (2) accidental dual-store, (3) silent-success failure modes. To those, 2026-05-31 adds a fourth, freshly demonstrated: **ad-hoc per-box / session-file fixes for what are actually shared code defects.** The resume-cap orphan was (briefly) attacked with session-file surgery before being correctly handed to Cairn as a converter/cap code fix. The standing rule: shared defects get fixed in source by their owner and pulled by every box — not patched per-agent. (See `feedback_deployment_discipline_git_not_rsync`, `feedback_cross_model_tool_orphans`.)
